# Mac as a conditional second herdr source (loopback sshd + reverse tunnel)

The primary public relay runs on a Linux host and polls its own machine. This setup adds the Mac
as an **optional, conditional** second source the relay can poll over SSH, without opening any
inbound port on the Mac. Everything is outbound from the Mac and bound to loopback end to end.

## Topology

```
relay host (HERDR_REMOTES=<mac-alias>)
   │  ssh 127.0.0.1:2223            (alias: HostName 127.0.0.1, Port 2223, key auth)
   ▼
relay's 127.0.0.1:2223  ◄── ssh -R 2223:127.0.0.1:2222 ── Mac LaunchAgent com.pf.herdr-mac-tunnel
                                                         │
                                            Mac loopback sshd :2222 (com.pf.herdr-mac-sshd)
                                                         │
                                            herdr pane list on the Mac
```

- The Mac runs a **dedicated sshd** on `127.0.0.1:2222` — not the system sshd, not exposed on any
  interface, key-only (`PasswordAuthentication no`, `UsePAM no`, `PermitRootLogin no`).
- A reverse tunnel connects **outbound** from the Mac and registers `127.0.0.1:2223` on the relay.
- The relay's `~/.ssh/config` aliases that loopback port, and `HERDR_REMOTES` lists the alias, so
  the relay treats the Mac exactly like any other SSH remote. Removing the alias from
  `HERDR_REMOTES` (or the tunnel going down) simply removes the source; the relay stays up.

## Files in this directory (templates, not the live units)

| file | installed location on the Mac |
|---|---|
| `sshd_config.template` | `~/.config/herdr-mac-sshd/sshd_config` |
| `com.pf.herdr-mac-sshd.plist.template` | `~/Library/LaunchAgents/com.pf.herdr-mac-sshd.plist` |
| `com.pf.herdr-mac-tunnel.plist.template` | `~/Library/LaunchAgents/com.pf.herdr-mac-tunnel.plist` |

Replace `ABS_HOME` (absolute home path; sshd/plist do not expand `~`) and `RELAY_HOST` (an
`~/.ssh/config` alias, so no literal address is committed). The live units are hand-managed rather
than generated by nix activation, so updating these templates does not change the running agents.

## Setup (once per Mac)

```sh
mkdir -p ~/.config/herdr-mac-sshd
# Dedicated host key — generated, never committed.
ssh-keygen -q -t ed25519 -N '' -f ~/.config/herdr-mac-sshd/ssh_host_ed25519_key
# Render the templates with $HOME and the relay alias, then install the two agents.
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.pf.herdr-mac-sshd.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.pf.herdr-mac-tunnel.plist
```

On the relay host, add the loopback alias and the source (key-based, no password):

```sshconfig
Host mac-herdr
  HostName 127.0.0.1
  Port 2223
  User <mac-user>
  BatchMode yes
  ConnectTimeout 8
  ServerAliveInterval 15
```

then include `mac-herdr` in `HERDR_REMOTES` in the relay's `config.env` and restart the relay.
The Mac's public key must already be in the relay's `authorized_keys` for the outbound tunnel,
and the relay's public key in the Mac's `~/.ssh/authorized_keys` for the polling direction.

## Health checks

```sh
# Mac: both agents loaded, sshd listening on loopback.
launchctl print gui/$(id -u)/com.pf.herdr-mac-sshd    | grep -E 'state ='
launchctl print gui/$(id -u)/com.pf.herdr-mac-tunnel  | grep -E 'state ='
nc -z 127.0.0.1 2222 && echo 'local sshd up'

# Relay: the tunnel port is listening and the alias resolves through it.
nc -z 127.0.0.1 2223 && echo 'tunnel reachable'
ssh -o BatchMode=yes mac-herdr 'true' && echo 'relay can poll the Mac'
```

The relay's poll log shows the source alongside its other remotes (`Polling: local, mac-herdr`).

## Rollback

- Stop adding the source first: remove the alias from `HERDR_REMOTES` on the relay and restart it.
- Tear down the Mac agents:
  `launchctl bootout gui/$(id -u)/com.pf.herdr-mac-tunnel` and
  `launchctl bootout gui/$(id -u)/com.pf.herdr-mac-sshd`.
- The state dir can then be removed; the host key inside it is unique to this loopback sshd.

## Deliberately not committed

The live `~/.config/herdr-mac-sshd/` holds the generated `ssh_host_ed25519_key` (a private host
key), runtime `*.pid` and `*.log` files. Only the templates above belong in version control; never
copy the key, logs or pid files here. No secret, address or password appears in these templates.
